Decision: style on hosts without a shadow root

<neo-resizable> keeps the size the user drags in the host style, and <neo-elastic> keeps its pinned height there. A morph sets style to the server's and drops the rest, which resets the size. Neither host has a shadow root to hold a :host rule, as <neo-carousel> now does.

The options, each run below by a small element on the same markup. The trade-offs follow the table.

  • Today. Write style.width on the host.
  • A, shadow root. Attach a shadow root with 1 <slot> and keep :host { width: 304px !important } in an adopted sheet.
  • B, observed style. Write style.width and re-apply it from a MutationObserver on style after a morph.

Every server copy carries style="outline: 2px dashed tomato", which the server owns. The toy hosts are page-styled display: flex; gap: 12px; width: 12rem, and their first child is page-styled green.

Trade-offs

"Table" marks a point the table above measures. "Checked" marks one tested separately in Chrome 158.

Today, style on the host

Pros

  • No extra DOM and no observer.
  • The value shows in the style attribute in devtools.
  • Page CSS with !important can override it.

Cons

  • A morph drops it, and the size resets. For <neo-resizable> that includes the width attribute value the component copies into style, which leaves it full width (table).
  • It writes an attribute the server owns, against the ownership rule.
  • The server can't send its own style without wiping what the component wrote.

A, shadow root with a :host rule

Pros

  • A morph can't reach the rule. The size survives with 0 writes per morph (table).
  • The server's own style stays separate and intact (table).
  • No observer, which means no mutation records for other scripts to see.
  • Same mechanism as <neo-carousel> now, and as option C of the child-state decision, which gives the kit 1 pattern for both.
  • Complies with the ownership rule as written.

Cons

  • It changes the host's structure. Its children render through the slot from then on. Page CSS still reaches them and the host's flex layout still applies (table).
  • A child with a slot attribute matches no slot and stops rendering (checked). Manual slot assignment, as in <neo-lightbox> and <neo-popover>, avoids this (checked), at the cost of re-assigning the children on every child change.
  • !important is required, because page CSS on the host beats a normal :host rule. A shadow !important also beats the page's !important (checked), which means the page can no longer override that property at all.
  • The value doesn't show in the style attribute. Devtools lists it under the shadow root's adopted sheet.
  • The host can't take another shadow root later. Code that calls attachShadow on it throws.
  • 1 shadow root and 1 CSSStyleSheet per instance.

B, style re-applied by an observer

Pros

  • No structural change to the host.
  • The value stays visible in the style attribute.
  • The page's !important still overrides it (checked).
  • The smallest code change: 1 observer per host, like the ARIA re-application.
  • The observer runs before the next paint, and no reset shows (table).

Cons

  • It still writes an attribute the server owns. The ownership rule needs an exception that makes style partly managed.
  • 1 write per host per morph (table). Each is a mutation record other scripts see.
  • The equality check must compare the value the browser reads back. style.width returns 304px for 304.0px and calc(104px) for calc(100px + 4px) (checked). Comparing against the unnormalized value rewrites on every callback, which loops.
  • Code that reads layout during the morph, in the same task, sees the server's size. The observer only runs afterwards.
