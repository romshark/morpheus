Decision: state on page-rendered children

<neo-avatars> and <neo-breadcrumb> hide children the page renders by writing data-neo-avatars-hidden and data-neo-breadcrumb-hidden on them. A morph strips both. The children (<neo-avatar>, links, list items) are no custom elements with a class, which leaves them no :state(). The host needs another way to hide them.

The options, each run below by a small element on the same 6 children. The trade-offs follow the table.

  • A, managed marker. Keep the data-* marker and re-apply it from an attribute observer after a strip, like role and ARIA. Kit CSS hides it with display: none !important.
  • B, hidden. Toggle the hidden attribute and re-apply it the same way.
  • C, shadow root. Give the host a shadow root with 1 <slot> and keep a ::slotted(:nth-child(n+4)) { display: none !important } rule in an adopted sheet.

Every element shows the first 3 children and hides the rest. Child 2 carries a server-rendered hidden, and child 5 has page CSS display: inline-flex.

Trade-offs

"Table" marks a point the table above measures. "Checked" marks one tested separately in Chrome 158.

Today, a marker written once

Pros

  • The hidden state shows in the DOM, and 1 attribute selector styles it.

Cons

  • A morph strips it and nothing restores it. <neo-avatars> shows all 6 avatars and no "+N" chip, still 1s later (table).
  • Runtime state in an attribute, against the rule that a data-neo-* mark names a part.

A, marker re-applied by an observer

Pros

  • No structural change to the host.
  • The hidden state stays visible in the DOM, and page CSS can still select hidden items, for example to fade them instead of hiding them.
  • Respects a server hidden and beats page display (table).
  • Same mechanism as the ARIA re-application the kit already uses.

Cons

  • It writes on children the server owns: 1 write per hidden item per morph (table), each a mutation record other scripts see.
  • The rule that marks name parts, not state, needs an exception for children that aren't kit elements.
  • The kit CSS needs !important to beat page display.

B, hidden

Pros

  • A standard attribute that needs no kit CSS.
  • Hidden items leave the accessibility tree, as with the other options.

Cons

  • Page CSS that sets display on an item beats it, because [hidden] { display: none } is a user-agent rule (child 5, table).
  • The host can't tell its own hidden from one the server rendered, and it revealed child 2 (table).
  • It fights the server on every morph: the server sends its hidden, and the observer rewrites it (table, 4 writes).
  • It writes on children the server owns, as A does.

C, shadow root with a ::slotted() rule

Pros

  • 0 writes on the children, and a morph can't reach the rule (table).
  • Respects a server hidden and beats page display (table).
  • Same mechanism as <neo-carousel> now, and as option A of the host-style decision, which gives the kit 1 pattern for both.
  • Complies with the rules as written.

Cons

  • It changes the host's structure. A child with a slot attribute matches no slot and stops rendering (checked), unless the host assigns its children manually as <neo-lightbox> does (checked). The host can't take another shadow root later.
  • ::slotted() matches only direct children. Avatars, crumbs and separators are direct children today, and future markup must keep them so.
  • The hidden set must be expressible as position selectors. A contiguous run fits, such as the breadcrumb's middle with :nth-child(n+2):nth-last-child(n+3). An arbitrary set needs 1 selector per item.
  • A shadow !important beats the page's !important (checked), and the page can't show an item the host hides.
  • The hidden state leaves the DOM. Page CSS or tests that select [data-neo-avatars-hidden] break. The doc pages don't list it as a hook, and only the kit CSS uses it (neo-avatar.css, neo-breadcrumb.css).
