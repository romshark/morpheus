neo-carousel: state lost on a morph

<neo-carousel> writes attributes at runtime that no server template renders: id, role and aria-roledescription on the host, tabindex="0" on the track, and id, role, aria-roledescription, aria-label and data-neo-carousel-slide-visibility on each slide. A morph strips every attribute the template lacks and keeps the elements. The carousel sets the host and track attributes only on connect, and the slide ARIA only in a sync that a value or child change starts. After a morph that keeps value, they stay gone. The track can no longer take focus, and screen readers lose the carousel and slide roles.

The slide visibility marker returns about 200ms later. Until then, the visible slides dim under highlight-active. DESIGN.md "Internal state" puts this marker in a custom state on <neo-carousel-slide>, which a morph can't reach, and the ARIA attributes and tabindex need re-applying after a strip, as observeManagedAttrs does in other components.

  1. Click Morph. It reconciles the live carousel's attributes against the server markup below, as a Datastar morph does.
  2. Every row should read PASS. Before the fix, the ARIA, id and tabindex rows fail, and the visible slides dim at 100ms.
  3. In Safari, press Tab from the Reset button. Before the morph, Tab reaches a dot and then the track. After it, Tab skips the track. Chrome focuses a scroll container without tabindex and still reaches it.
